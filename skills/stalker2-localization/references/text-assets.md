# Text assets and the cooked localization database

What the Zone Kit's Text Tool writes, what the cook makes of it, and how to check a staged build.
Adapted from the Stalker 2 modding harness (github.com/noahsemus/stalker2-modding-harness, MIT, copyright Noah Semus); this part was contributed there by sdwvit.

## Source asset: `LocalizationModTextToolAsset`
The Text Tool creates it in the mod's `Content`. Its single export is

```
LocalizedTexts: Array<{ SID: FString, LanguagesToLocalizedStrings: Map<ELocalizationLanguage, FString> }>
```

- SIDs are free-form strings.
- Language keys are the enum members exactly: `English, Ukrainian, German, French, SpanishEuropean, Italian, Polish,
  Czech, Turkish, Serbian, PortugalBrazilian, SpanishLatinoAmerican, Arabic, ChineseSimplified, ChineseTraditional,
  Japanese, Korean, Russian` (the same order as the culture folders `en uk de fr es it pl cs tr sr pt-BR es-419 ar
  zh-Hans zh-Hant ja ko ru`).

## Dialog text asset: `/Script/ModKitEditor.DialogModTextToolAsset`
Export `Dialogs`:

```
Dialogs: Array<DialogTopicTextTool_ModEditor>
  TextToolTopicName, SID = <ModName>_<TopicName>       GlobalWFR.SID  = sid_topic_<SID>
  TopicCharacterSIDs: Array<Name>
  Labels: Array<DialogLabelTextTool_ModEditor>
    TextToolLabelName, SID = <topic SID>_<LabelName>   LabelWFR.SID   = sid_label_<SID>
    Phrases: Array<DialogPhraseTextTool_ModEditor>
      SID = <label SID>_000, _001, ...                 PhraseText.SID = sid_phrase_<SID>
      Character: Name (speaker, e.g. a vanilla character id; None when unset)
```

- `GlobalWFR` / `LabelWFR` / `PhraseText` are each `{ SID, LanguagesToLocalizedStrings }`.
- The scheme matches what the game expects of `DialogPrototype.TextToolPhraseSID` (label = phrase SID minus
  `_<NNN>`). A label groups a reply option with the lines spoken after it.
- `Character` must be a known TextTool character for voice to register (stalker2-voiceover).
- Whether the cook-time gather picks up dialog text by itself: not verified.

## What the cook produces
- The editor gathers every text asset into one generated package. Cook log lines:
  `LogModTextToolManager: Created mod localization database with N localized texts from M ModTextToolAsset assets`
  and `LogModAssetCreator: Saved ModLocalizationDatabaseDataAsset
  '../../Mods/<Mod>/Content/Autogenerated_<n>_LocalizationDatabase.uasset'`.
- Its export is `LocalizationDatabase: TMap<FString SID, FModLocalizationLocalizedStringsContainer>`, holding the
  same language map. `<n>` is the save's Unix timestamp; once cooked, that name is the mod's identity.
- The `.uplugin` lists no assets: anything in `Content` gets cooked.
- **One database per mod.** A second `Autogenerated_<m>_LocalizationDatabase` of the same SIDs left in `Content`
  (for example after copying assets between machines) is cooked too, and the classifier can put the two in
  different containers (seen: one in OverrideContent only, the other in both). Delete the stale one.

## Package identity
- Copying another mod's text asset and renaming the file leaves its package name pointing at that mod; create a
  fresh asset in the Text Tool.
- The asset's `LocalizationId` namespaces its gathered text: two mods must not share one.
- A text package's name is stored in the summary `PackageName`, twice in the name table and again in the
  asset-registry section, so a rename is not a string replace.

## Checking a staged build
- Extract the staged container and search it for the SID. The SID is stored as an FString, so a plain byte or UTF-16
  search of the `.ucas` finds it.
- On Linux: `strings -a <staged>.ucas | grep <SID>` (8-bit text; add `-el` for UTF-16 strings).

## Linux
- The game's paks and the kit read the same from a Linux host:
  `repak list "<game>/Stalker2/Content/Paks/pakchunk0-Windows.pak" | grep locres`, then
  `repak get <pak> Stalker2/Content/Localization/Game/<culture>/Game.locres > <culture>.locres` (no IoStore tooling
  needed).
- Text assets and the database are plain UE packages; the Mod Editor running under Proton writes the same files as
  on Windows. More: stalker2-linux.
